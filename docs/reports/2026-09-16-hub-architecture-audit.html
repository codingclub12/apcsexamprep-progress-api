Method

What was measured, and what was not

Every figure on this page marked as measured came from fetching the live storefront today through lib/storefront-fetch.js, which refuses a body that is not provably a rendered page. The sample is 60 pages taken at a fixed stride across all 1,360 handles in sitemap_pages_1.xml, so it is spread across every course rather than clustered.

The correction that matters

There is no leftover Dawn mega-menu. snippets/header-mega-menu.liquid, ap-csa-megamenu.liquid and ap-cyber-megamenu.liquid are dead files: nothing renders them, so they contribute zero links to any page. Deleting them, which is what the original order of work asked for first, would have changed nothing on the live site while reading as though the problem was solved.

The duplication is real, and it is bigger. sections/header.liquid carries its own custom mega menu of 144 links and renders on every page, while snippets/apcs-nav-source.liquid renders a second, newer nav of 118 links from theme.liquid. Both ship. The first has no layout CSS left, which is why the site looks rebuilt while the markup is not.

Findings

Ranked by what it costs

Ordered by consequence, not by effort. The numbering is the ranking.

01

Breadcrumb schema named the wrong course and a dead page

Shipped and verified

The branch chain tested unit-1 through unit-4 inside its first branch, so ap-cybersecurity-unit-1-social-engineering matched AP Computer Science A and never reached the Cybersecurity branch. 147 handles were affected. The parent it named, /pages/ap-csa-exam-prep, is a 404, and three more named parents are 301s. All 30 URLs were hardcoded on the non-www host while every canonical is www.

Fixed in PR #120, merged into the connected branch and live: course branches reordered, targets repointed to pages that answer 200, hosts read shop.url, and the snippet now stands down where the page body already states its trail. Re-derived across all 1,360 handles at zero wrong-course parents, and mutation tested by restoring the old order, which puts it back to 147.

02

Two full navigation systems in every page

Open, next push

144 links from sections/header.liquid and 118 from apcs-nav-source.liquid, on all 60 sampled pages. Around 262 of a lesson page's 407 links are navigation chrome repeated on every URL on the site.

The fix is to delete the mega nav markup from sections/header.liquid, not the three dead snippets. It needs a visual check after the push, because that section still carries the pill styling that the surviving nav does not define.

03

Six hub URLs serve an empty shell

Sheet staged

/pages/ap-csa, ap-csp, practice-exams, flashcards, bundles and quick-reference each return 200 with the same content: a title and the global contact widget. Measured inside <main> they run 2,314 to 2,315 words, all of it shared chrome. The last four share a slug with a real collection they have been competing against.

The redirect sheet is written and every target was status checked at 200 before its row existed. It is a no-op until somebody unpublishes the pages, which is why it ships with an ordered runbook rather than as a file to import.

04

Two H1s on effectively every page

Open

59 of 60. This is a template defect rather than a content one, so it is one fix in the layout rather than 1,300 page edits. It sits below the nav work because a second H1 costs less than 262 repeated links.

05

Hub pages compete with the pages they should feed

Needs the traffic data

Several pages per course answer the same query, and the reported pattern is that the hub style pages sit at positions 20 to 68 while the destination pages sit at 5 to 10. That pattern is the reason for the architecture below.

These positions are the part this session could not read. The consolidation is worth doing on structure alone, but which URL keeps the role is a decision that needs the numbers, and picking wrong costs a ranking page.

Target state

Six roles, one URL each

Every course gets the same six roles: Course hub, Unit hubs, Study, Practice, Exam, Teachers. Each role belongs to exactly one URL, and the nav, the homepage, the visible breadcrumb and the schema all name that same URL. Small courses fold roles into the course hub rather than growing empty pages for them.

Three rules decide every individual case. Keep the URL that already ranks and redirect the competitors into it. Give distinct sub-topics their own child pages, linked both ways, the way FRQs by year and FRQs by topic are genuinely different questions. Never rename anything that earns clicks.

Already aligned

The breadcrumb fix shipped today points CSA at ap-csa-course and CSP at ap-csp-course, which are the hubs this table keeps. So the schema is already pointing at the target architecture rather than at the current one, and the merges will not need a second pass through that snippet.

Sequence

Order of work

  1. Breadcrumb schema. Shipped. PR #120 merged into the connected branch, deploy confirmed against the live storefront: duplicates 29 to 0, dead parent 35 to 0, and no page lost its schema.
  2. Delete the mega nav from sections/header.liquid. The section itself, not the three dead snippets. Re-check button and title colours after the push, since that section defines pill styling nothing else does.
  3. Unpublish the six empty pages, then import the stage 1 redirects. In that order. Shopify ignores a redirect while a page still resolves, so importing first produces six redirects that silently never fire and a log that looks like success.
  4. Cyber consolidation, before October and ahead of the November 1 indexing deadline.
  5. CSA and CSP hub merges, updating breadcrumb root, nav and homepage in the same push so the four never disagree.
  6. Port content first for the pages that need it, the two CSA unit guides, exam-review, CSP study-guides and the Networking exam page, and only then redirect them.
  7. Fix the 14 non-www breadcrumb URLs in page bodies, which the theme cannot reach.
  8. Repair the broken links and re-crawl, including the 31 self-redirecting links on ap-csa-frqs-by-topic that reload the page a student just clicked away from.
