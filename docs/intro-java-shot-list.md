## Before you start

Read this once. It is the difference between a set that looks professional and
one that looks like it was assembled over six months, which it will be.

- **Build each scenario for real and shoot as you go.** The lessons promise that
  every step leaves a scenario that compiles and runs. Shooting in order is how
  you find out whether that is actually true, and it is the one part of this
  that cannot be faked afterwards from a finished project.
- **Fix the window size before the first shot of a unit and do not touch it.**
  A set shot at three sizes reads as sloppy even when each individual shot is
  fine. 1440 by 900 is a good default.
- **Same scenario, same actors, same zoom** across a whole unit.
- **Crop to what the step is about.** If the step is about the class diagram,
  the shot is the class diagram, not the whole desktop.
- **No student names, no file paths with your username, no email in the title
  bar.** These pages are used by minors in schools.
- **Note the Greenfoot version** you shot against at the top of your notes. A
  version bump is a reshoot of the affected steps, and you will not remember.

## The pages work without these

Nothing is blocked. Until a shot is listed in `seed/intro-java-shots.js`, the
page prints its description as an instruction instead:

> On your screen: the class diagram panel, showing World with a subclass beneath
> it and Actor with several subclasses beneath it.

So you can ship the course today and add shots one at a time, in any order,
and every one you add upgrades a page with no other change.

## How to add one

1. Take the shot.
2. Upload it to the theme under the **Upload as** name below (the theme
   flattens the folders, so the slashes become dashes).
3. Add the **Path** to the `AVAILABLE` list in `seed/intro-java-shots.js`.
4. `npm run smoke:introjava`. A path that does not match a real shot fails,
   so a typo cannot silently show nothing.
