# Matrixify import, 2026-08-26

Three sheets, 45 records. Generated by `node scripts/seo-metadata-csv.js imports/2026-08-26`
from `seed/seo-rewrites.js`. Regenerate rather than hand-edit: the generator
enforces the rules and a hand edit does not.

```
seo-pages.csv         25 rows   Handle, Command, SEO Title, SEO Description
seo-products.csv      13 rows   Handle, Command, SEO Title
seo-collections.csv    7 rows   Handle, Command, SEO Title, SEO Description
```

## How to import

Matrixify > Import > pick the file > Import. Once per sheet, in any order.
The sheets are independent.

Matrixify reads the sheet type from the columns, so no template selection is
needed. Do a dry run first if you want the diff before it lands.

## Why these are safe to import

Three properties, all asserted by `smoke/seo-metadata-csv.js` so they cannot
quietly stop being true.

**No content column exists.** The header is `Handle`, `Command`, and the SEO
fields. There is no `Body HTML`, no `Title`, no `Published`. Matrixify writes the
columns it is given and leaves out every column it is not, so nothing in these
files can touch a page body even if every value were wrong. The 2026-08-22
incident that blanked a live student page was a sheet carrying `Body HTML`.
`assertHeaderIsSafe()` fails the build if a content column is ever added.

**Every command is MERGE.** MERGE updates a record that already exists and never
creates one, so a typo'd handle is a no-op rather than a new blank page. All 45
handles were also checked against the live sitemap before this sheet was written,
and all 45 exist.

**No cell is empty.** This is the one that nearly went wrong. An empty cell in a
provided column CLEARS the stored value rather than skipping it. The first draft
of the generator emitted a fixed four-column header, which gave the products
sheet 13 empty `SEO Description` cells and would have wiped the description on
every teacher bundle on the site. The generator now derives the header from the
rows: a column appears only when every row in that sheet supplies it, and a sheet
whose rows disagree is refused rather than blank-filled. That is why
`seo-products.csv` has no description column at all.

## What changes

**Pages, 25.** The hub rewrites, plus every page carrying a school year that has
ended. Includes `ap-computer-science-principles-resources`, a nav-linked CSP page
whose description described AP CSA and the 4-unit structure; the four Command
Centers, retitled from "command center" to "pacing guide", which is what a
teacher actually searches for; and both score calculators, moved from 2026 to
2027.

**Products, 13.** The three teacher bundles carrying the store name twice, the
two titles cut off mid-word, and every product still advertising the 2025-2026
exam while on sale. Titles only. No product description is touched.

**Collections, 7.** Every collection had no meta description at all, so these are
all new descriptions plus titles.

## What this does NOT fix

Worth knowing before you look at the site afterwards and wonder why it still
looks wrong in places.

- **The duplicate `Get in Touch` H1 on 47 of 50 pages.** That is a contact
  section in the shared theme template, not page data. One theme edit, and theme
  work deploys through the connected branch, not `main`.
- **The title string rendered as a visible H1 on 11 pages.** That text lives in
  the page bodies, so it needs a body sheet, which is a different and more
  dangerous class of import. Not in this batch on purpose.
- **`robots.txt`, which serves a 1-byte body.** Theme file.
- **The eight competing AP Cybersecurity overview URLs.** Consolidating them
  means redirecting, and picking which URL survives without Search Console click
  data is guessing. Rewriting a page is safe without GSC. Redirecting one is not.

## After importing

The daily audit (`.github/workflows/site-audit.yml`, 09:00 UTC) recrawls and will
report these as resolved on the next run. To check immediately:

```
node scripts/site-crawl.js --full --budget 0 --out /tmp/after.json
```

The `stale-year`, `brand-doubled` and `meta-scraped` counts should fall to near
zero. `h1-duplicate` will not move, because that one is the theme.
